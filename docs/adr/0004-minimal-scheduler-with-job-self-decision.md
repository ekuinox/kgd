# 0004: スケジューラは最小の固定間隔ランナー + ジョブ内自己判定

## ステータス

受理 (2026-06-11, #70)

## 文脈

リファクタ前の定時処理は 60 秒固定の tokio ループに自動クローズと毎時同期が直書きされており、
処理を追加するたびにループ本体を書き換える必要があった (#70)。
cron 式などを持つ高機能なスケジューラを導入する選択肢もあった。

## 決定

スケジューラは「一定間隔で登録ジョブの tick() を順に呼ぶ。失敗してもほかのジョブは実行する」
だけの最小実装とし、「今実行すべきか」(時刻境界・時間帯スロット・重複抑止) の判定は
各ジョブ側 (ユースケース内の純粋関数 + Clock ポート) が持つ。

- ScheduledJob trait と各ジョブ (AutoCloseJob / HourlySyncJob) は kgd-application
- tokio interval を回すランナー (Scheduler) は kgd-infrastructure

## 結果

- ジョブの追加は trait 実装と bootstrap での register のみで済む
- 時刻に依存する判定が Clock 注入の純粋関数になり、実時間を待たずにテストできる
- 「1 tick で全ジョブを呼ぶ・失敗しても継続する」というランナーの性質は
  ジョブのスタブ実装でテストする
- ジョブごとに異なる間隔が必要になった場合は、ジョブ内の自己判定で吸収するか、
  本 ADR を更新してランナーを拡張する

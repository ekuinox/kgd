# 0008: 一日の始まりより前でも次の日報を開始できるようにする

## ステータス

受理 (2026-09-03, [ADR-0007](0007-diary-day-starts-at-day-start-hour.md) の結果を一部改める)

## 文脈

[ADR-0007](0007-diary-day-starts-at-day-start-hour.md) で日報の一日の始まりを `day_start_hour`
で定義した。0 時を過ぎた投稿は前日の日報の続きとして扱われ、日報日が変わるのは
`day_start_hour` になってからである。その結果として、深夜に「クローズ & 新規作成」ボタンを
押しても新しい日報は作られず、既存の日報が再開されるだけになっていた。

運用ではこれが足りない。日付が変わってから `day_start_hour` までの間に、
その日の日報を先に始めたいことがある。いまは precheck が今の日報日を見て
`AlreadyLatest` を返すため、ボタンを押しても何も起きない。
`day_start_hour` を待つか、設定値そのものを下げるしか手段が無かった。

設定値を下げる回避策は使えない。`day_start_hour` は日付境界と自動クローズ通知の
両方を兼ねているので、下げると深夜の投稿が翌日の日報へ移ってしまう。
ADR-0007 が解こうとした問題に戻るだけである。

## 決定

**0 時から `day_start_hour` までの間に限り、クローズ & 新規作成は
「まだ始まっていない次の日報日」を対象にする。** この時間帯かどうかの判定と対象日は
ドメイン層の `DiaryCalendar::early_next_day` が返す。該当しない時間帯では `None` を返し、
従来どおり今の日報日が対象になる。`day_start_hour` が 0 ならこの時間帯は存在しない。

**早出しはボタンを押したときだけ起きる。** 日付境界の定義は ADR-0007 のまま変えない。
ボタンを押さなければ深夜の投稿は前日の日報の続きとして扱われる。
`/diary new` は早出しの起点にしない。入り口を一つに絞ることで、
「気付かないうちに翌日の日報が始まっていた」という状態を防ぐ。

**早出しした日報がある間は、それを現在の日報として扱う。** 転記と `/diary new` は
「早出しした日報があればそちら、無ければ今の日報日」の順で引く
(`kgd-application` の `find_current_entry`)。この解決を入れないと、早出し後の深夜の投稿が
クローズ済みの前日スレッドへ転記され、早出しが機能しない。

**毎時の再同期の対象範囲の終端を早出し先まで広げる。** 範囲は今の日報日で終わっていたため、
翌日付の日報スレッドが再同期の対象から外れていた。

**設定項目は増やさない。** 早出しできる時間帯は `day_start_hour` から導かれる。

## 結果

深夜でもボタンひとつで次の日の日報を始められる。以降の投稿は新しい日報スレッドと
Notion ページへ転記される。

早出し後は `day_start_hour` を跨いでも自動クローズ通知は出ない。
最新エントリが今の日報日以降なら通知しないという既存のガードがそのまま効く。

0 時を過ぎてからのボタン押下は、これまで何も起こさなかったが、これからは新しい日報を作る。
誤って押したときの結果が変わる。

早出しの窓の間だけ、毎時の再同期の対象が 3 日分から 4 日分になる。

ADR-0007 の「深夜に押しても新規作成されない」という結果はこの ADR で置き換わる。
日付境界の定義、`day_start_hour` の意味、永続化済みの `diary_entries.date` の表現は変えていない。
